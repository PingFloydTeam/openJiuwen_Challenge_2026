**Предлагаемый заголовок:** test: независимое ревью, 19 регрессионных тестов и проверяющий стенд

Решатель проходит исходные проверки и восемь официальных примеров, но на дополнительных сценариях теряет корректные ответы, преждевременно объявляет задачи невыполнимыми и не восстанавливается после некоторых ошибок прокси. Этот PR фиксирует воспроизводимые случаи, результаты независимого ревью и порядок исправлений.

Проверяемая версия — `121f6c14fed39a00ad455d809577f484024b09ab`. Код решателя, зависимости и Dockerfile не изменены. Уточнения организаторов с последующих созвонов приняты выше исходного регламента.

**Состояние тестов — ожидаемые падения на текущем решателе**

Новые тесты проверяют требуемое поведение и намеренно не помечены `expectedFailure`. Сейчас 16 из 19 падают, подтверждая существующие дефекты; 3 положительных контроля проходят. После исправлений тот же набор должен стать зелёным. Это PR с тестами и результатами ревью, а не с исправленным решателем. Нельзя считать его проверкой готовности текущей версии к финалу.

| Проверка | Зафиксированный результат |
|---|---|
| Исходные Linux-проверки | 75/75 проходят |
| Новые независимые тесты | 19: 16 падают, 3 проходят |
| Официальные примеры, offline, реальный openJiuwen | 8/8, 20/20 баллов, 0 токенов |
| Те же примеры с локальным HTTP-прокси и сценарными ответами | 8/8, 20/20; 10 вызовов; 11 605 входных + 362 выходных; 1522,5 синтетических эквивалента |
| Конкурсный Docker-образ | Собран; 1,39 ГБ по `docker images` |
| Холодная сборка | Общий шаг установки зависимостей занял 1017,3 с при лимите сборки 1000 с |
| Живой NeuralDeep | Не проверен: соединения завершились таймаутами до аутентификации, ключ не отправлялся |

В HTTP replay 110 reasoning-токенов входят в выходные и учтены один раз. Это синтетический расход тестового сервера, не биллинг NeuralDeep. Проверена среда Linux arm64, Python 3.13.7, openJiuwen 0.1.19; linux/amd64 не проверен.

**Подтверждённые замечания**

| ID | Приоритет | Дефект и ожидаемая доработка |

| R02 | P1 | Ремонт `average()` проходит видимый тест, но нарушает явное условие `average([]) == 0`. Проверять контракт до принятия исправления. |

| R04 | P1 | Временный HTTP 429 с `Retry-After` блокирует все дальнейшие обращения. Отделить временный rate limit от постоянного отказа и добавить ограниченные повторы. |
| R05 | P1 | `finish_reason=length` завершает задачу без повтора при доступном бюджете. Добавить восстановление с сохранением расхода первого запроса. |

| R08 | P2 | Полный ограниченный перебор не принимается из-за требования конкретного инструмента `integer_inverse`. Проверять покрытие ограничений и доказательство результата. |
| R09 | P2 | Сущность, найденная после трёх переходов, запрещается при следующем `lookup`. Расширять допустимые сущности подтверждёнными результатами инструментов. |

| R11 | P2 | Runtime fixture считается отсутствующим входом, а последовательные результаты stateful-функции — противоречием. Учитывать роль данных и состояние. |

Отдельный P1-риск — время холодной сборки. Зафиксированное превышение сильно зависит от скачивания зависимостей; оно не доказывает превышение на сети жюри. Последующая быстрая сборка с кешем этот риск не снимает.

В опубликованном прогоне с бюджетом 100 000 осталось 83 381,9 эквивалента, но семь выполнимых задач были пропущены. Поэтому сначала нужно исправить отказы и повторные попытки, затем измерять пользу энкодера. Сейчас энкодер есть только как эксперимент в `bench/encoder.py`, runtime его не использует. Целевые 16 падений не являются оценкой доли ошибок на финальном наборе.

**Как воспроизвести**

Команды выполняются из корня репозитория. Для сборки нужен доступ к зависимостям; сами регрессионные тесты не требуют сети, API-ключа или оплаты.

```sh
docker build --target bench -t ping-floyd:independent-review .

docker run --rm --network none --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 -e HOME=/tmp \
  -v "$PWD/tests:/review-tests:ro" \
  --workdir /app --entrypoint python ping-floyd:independent-review \
  -m unittest discover -s /review-tests -p 'test_review_*.py' -v
```

Ожидаемый exit code новых тестов на проверенном commit: `1` (16 failures). Исходный набор запускается отдельно, ожидаемый код: `0`.

```sh
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 -e HOME=/tmp \
  --workdir /app --entrypoint python ping-floyd:independent-review \
  -m unittest discover -s bench -t /app -p '*checks.py' -v

python3 reviews/2026-11-12/run_official.py \
  /absolute/path/to/task-dir \
  runs/review-official-new --image ping-floyd:independent-review
```

В последней команде нужен путь к исходным примерам организаторов с `expected`; каталог результата должен быть новым. Оригиналы заданий скрипт не меняет. Подробности живого прогона через переменные окружения приведены в отчёте; успешный живой прогон в этом PR не заявляется.
