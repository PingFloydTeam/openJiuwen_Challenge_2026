# Ping Floyd · openJiuwen Challenge 2026

Харнесс команды Ping Floyd решает задачи четырёх типов: `math`, `search`, `data_analysis` и `coding`. Для каждой задачи openJiuwen 0.1.19 запускает workflow `Start → Solve → Save → End`. Сначала харнесс пробует локальное решение. Если данных достаточно, но локальный алгоритм не подходит, планировщик выбирает задачу для обращения к модели. Модель составляет план или вызывает инструмент, а вычисления и проверка выполняются локально.

## Сборка и запуск

```sh
docker build --target contest -t ping-floyd:contest .
```

Базовый образ Python 3.13.7 зафиксирован по digest, зависимости закреплены в `requirements.txt`. Они устанавливаются при сборке. Во время прогона харнесс обращается только к API по `LLM_BASE_URL`. Для сборки и проверки локально нужен Docker с Linux-контейнерами.

Организаторы передают `LLM_BASE_URL` и `LLM_API_KEY` через окружение. Для ручного прогона экспортируйте их в оболочке и используйте отдельную копию задач с доступом на запись. Пример запуска в сети организаторов `hack-net`:

```sh
mkdir -p "$PWD/out"
docker run --rm --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET=100000 \
  -e HOME=/tmp -e OUT=/out/answers.txt \
  -v "$TASKS:/data/tasks:rw" -v "$PWD/out:/out:rw" \
  --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  ping-floyd:contest --tasks-dir /data/tasks
```

| Параметр | Назначение |
|---|---|
| `TASKS` или `--tasks-dir` | Каталог с подкаталогами задач. В каждом лежит `task.json`, а входные файлы находятся в `workspace/`. |
| `OUT` или `--out` | Необязательный общий файл решений или существующий каталог, в котором создаётся `answers.txt`. |
| `BUDGET` или `--budget` | Общий бюджет в выходных эквивалентах. Значение по умолчанию 100 000. |
| `LLM_BASE_URL`, `LLM_API_KEY` | Базовый URL и ключ прокси. К URL добавляется `/chat/completions`. |
| `--model`, `--workers`, `--seconds` | По умолчанию `qwen3.8-27b-noreason`, одна сессия и 3500 секунд. Допустимо от одной до пяти сессий. |
| `--offline`, `--trace` | Локальный прогон без LLM и дополнительный путь для журнала JSONL. События также идут в stdout. |

Ответ сохраняется атомарно в `answer.txt` рядом с `task.json`. Для проверенного coding-решения харнесс переносит изменения исходников из временной копии и записывает `DONE`. При пропуске файл ответа отсутствует. При заданном `OUT` общий снимок обновляется после каждого сохранения. Формат снимка — UTF-8 TSV с полями `task_id` и `answer`, без заголовка. При повторном запуске существующие ответы пропускаются, а снимок восстанавливается из них.

## Как расходуется бюджет

Локальные алгоритмы выполняются первыми и расходуют ноль токенов модели. Для оставшихся задач приоритет определяется как `reward × оценка вероятности решения / оценка стоимости`. Начальная стоимость зависит от типа и длины условия. По вызовам с подтверждённым `usage` оценка стоимости обновляется скользящим средним.

Расход считается в десятых долях выходного токена по формуле `input_tokens + 10 × output_tokens`. Токены рассуждения учитываются в выходе согласно формату `usage` прокси. Перед запросом харнесс резервирует оценку входа и максимальный выход в рамках общего бюджета и лимита задачи. Если ответ не содержит достоверного `usage`, резерв учитывается отдельно. Счётчик общий для всех сессий. Ограничения времени, шагов и попыток исправления ограничивают расход на одну задачу. Повторяющиеся пустые ответы прокси прекращают обращения к модели.

## Как определяются нерешаемые задачи

- **Математика.** Точные дроби, исключение переменных и ограниченный перебор помогают выявить противоречия и проверить единственность искомого значения.
- **Поиск и анализ данных.** `record_plan` выполняет фильтрацию, выбор ревизий, соединения и агрегацию. Инструмент проверяет согласованность результатов при равных приоритетах. Неизвестное значение учитывается, если от него зависит ответ.
- **Код.** Харнесс проверяет наличие необходимых файлов и совместимость явных требований. Правки проверяются в отдельной копии. Для поддерживаемых source-only задач выполняются публичные `unittest` и проверки явных примеров из условия. В Linux тесты выполняются с ограничениями seccomp. Публичные тесты остаются неизменными.
- **Пропуск.** При доказанной неоднозначности, отсутствии данных или исчерпании лимита без подтверждённого решения харнесс оставляет задачу без ответа. Эвристики пропуска могут ошибаться, что видно по результатам ниже.

## Эксперименты и траектории

На авторском контрольном наборе из 100 английских задач было по 25 задач каждого типа, из них 24 нерешаемые. Сравнивались исходная версия и финальный харнесс на одной модели `qwen3.8-27b-noreason`, с одной сессией и одинаковыми входами. Ниже выходные эквиваленты равны `output_tokens + input_tokens / 10`.

| Бюджет | Баллы исходной версии | Баллы финальной версии | Расход исходной версии | Расход финальной версии |
|---:|---:|---:|---:|---:|
| 100 000 | 62/233 | 219/233 | 21 964,7 | 16 618,1 |
| 5 000 | 0/233 | 90/233 | 4 811,4 | 4 878,2 |

В основном прогоне финальная версия решила 69 из 76 выполнимых задач, пропустила семь и один раз ответила на нерешаемую. Восемь официальных примеров дали 20/20 в режиме без LLM. Результаты получены на macOS с одним и тем же адаптером запуска тестов для обеих версий. Сборка финального образа и выполнение под ограничениями Linux требуют отдельной проверки.

В [траекториях](benchmarks/trajectories/) доступны события вызовов, имена инструментов, расход токенов и результаты по задачам. [Сводка](benchmarks/summary.json) содержит параметры прогонов и результаты проверки. Для повторения контрольного эксперимента:

```sh
docker build --target bench -t ping-floyd:bench .
python3 -m bench.frontier /tmp/ping-floyd-transfer
python3 -m bench.validation /tmp/ping-floyd-transfer /tmp/ping-floyd-run \
  --image ping-floyd:contest --bench-image ping-floyd:bench \
  --live --budget 100000 --seconds 3500
```

Генератор создаёт входы и эталоны отдельно. При эксперименте харнесс получает только каталог задач, а отдельный проверяющий процесс использует эталоны после прогона. Для локальной проверки без прокси уберите `--live`.
