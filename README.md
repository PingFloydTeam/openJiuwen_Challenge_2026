# Ping Floyd · openJiuwen Challenge 2026

Конкурсный харнесс для английских задач `math`, `search`, `data_analysis` и `coding`. Используется настоящий **openJiuwen 0.1.19**: workflow `Start → Solve → Save → End` и локальные инструменты `LocalFunction`. Сначала выполняются точные локальные алгоритмы; затем модель строит проверяемый план для оставшихся задач. Во время работы доступ к сети нужен только для прокси организаторов.

## Сборка

```sh
docker build -t ping-floyd:contest .
```

Последняя стадия Dockerfile — `contest`; `--target` не требуется. Python 3.13.7 закреплён по digest, версии всех зависимостей — в `requirements.txt`. Установка выполняется при сборке. В конечный образ входят только runtime и его зависимости: bench, эталоны, отчёты, `.env` и ключи не копируются. Веса моделей и данные при запуске не скачиваются.

## Запуск у жюри

`BUDGET` передаётся окружением **для конкретного прогона**. Его нельзя заменять фиксированным `100000` в команде запуска или образе. В примере `TASKS` — абсолютный путь на хосте к каталогу задач; `BUDGET`, `LLM_BASE_URL` и `LLM_API_KEY` уже экспортированы организаторами.

```sh
: "${TASKS:?Set the absolute task directory}"
: "${BUDGET:?Pass the budget supplied for this run}"
mkdir -p "$PWD/out"

docker run --rm --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET \
  -e TASKS=/data/tasks -e OUT=/out/answers.txt \
  -v "$TASKS:/data/tasks:rw" -v "$PWD/out:/out:rw" \
  --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  ping-floyd:contest
```

Совместим и вариант из регламента с `--workdir /app --entrypoint python`, после имени образа: `/app/run_agent.py --tasks-dir /data/tasks`. В этом варианте также нужно передать `-e BUDGET` и, для общего файла, `-e OUT` с writable mount. `HOME=/tmp` уже установлен в образе.

| Переменная / параметр | Значение |
|---|---|
| `BUDGET` | Неотрицательное целое число выходных эквивалентов. Верхний предел всех API-вызовов прогона; общего значения по умолчанию для онлайн-запуска нет. |
| `TASKS` / `--tasks-dir` | Каталог задач. В каждом подкаталоге — `task.json` и `workspace/`. |
| `OUT` / `--out` | Общий файл решений внутри writable mount. Для существующего каталога используется `answers.txt` внутри него. |
| `LLM_BASE_URL`, `LLM_API_KEY` | Адрес и ключ прокси. К базовому URL добавляется `/chat/completions`; обычно URL заканчивается `/v1`. |
| `--budget` | Дополнительный локальный предел. При заданном `BUDGET` действует **меньшее** из двух значений. Без `BUDGET` позволяет явно задать бюджет локального эксперимента. |
| `--model` / `LLM_MODEL` | По умолчанию `qwen3.8-27b-noreason`. Разрешены только четыре модели из регламента. |
| `--workers`, `--seconds` | По умолчанию одна сессия и 3500 секунд. От одной до пяти сессий. |
| `--offline` | Только локальные решатели, без API. Если бюджет не передан, принимается 0. |
| `--trace` | Дополнительный JSONL-журнал в writable-каталоге. События также выводятся в stdout. |
| `--retry-model`, `--retry-share`, `--no-auto-retry` | Ограниченный второй проход. Автоматически: бюджет ≥25 000 и остаток ≥50% после первого прохода; максимум 10% фактического бюджета. Его можно отключить. |

При `BUDGET=0` локальные решения сохраняются, запросов к модели нет. Невалидный или отрицательный `BUDGET` вызывает ошибку до запуска. Отсутствие одновременно `BUDGET` и явного `--budget` в онлайн-режиме также вызывает ошибку — скрытого перехода к 100k нет. `.env.example` предназначен для ручных локальных экспериментов; `.env` автоматически не загружается.

## Ответы и завершение

Ответ записывается атомарно в `answer.txt` **рядом с task.json**. Для coding проверенные изменения исходников переносятся из staging в workspace и сохраняется `DONE`. При пропуске answer.txt не создаётся. Публичные тесты не редактируются.

Если задан `OUT`, снимок обновляется после каждого сохранённого решения. Формат — UTF-8 TSV: `task_id<TAB>answer`, без заголовка; обратные слеши, табуляции и переводы строк экранируются. Точная грамматика общего файла в предоставленных материалах не определена; отдельные answer.txt сохраняются независимо от этого формата. Незаписываемый OUT диагностируется до запуска задач. Без OUT сохраняются только отдельные ответы.

SIGTERM, SIGINT, общий deadline и исчерпание бюджета прекращают новые обращения; уже сохранённые ответы остаются. Workflow ограничен меньшим из 180 секунд и остатка общего времени, отдельный API-запрос — 35 секундами. При повторном запуске существующие answer.txt пропускаются. Для продолжения прежнего API-бюджета передайте **его остаток**: межпроцессный расход автоматически не восстанавливается.

## Учёт расхода и выбор задач

Расход — `input_tokens / 10 + output_tokens`, включая reasoning согласно структуре usage. Внутренний счётчик целочисленный: `input_tokens + 10 × output_tokens`. Скидка за кеш провайдера не применяется. Перед вызовом резервируются вход и максимальный выход; резерв общий для всех сессий. Недостоверное usage и незавершённые запросы учитываются консервативным отдельным резервом. Временный 429 с подходящим Retry-After и усечённые ответы допускают ограниченные повторы с сохранением расхода всех попыток.

Локальный проход расходует ноль API-токенов. Далее приоритет — `reward × оценка успеха / оценка стоимости`, стоимость уточняется по подтверждённому usage. Ограничения задач и повторов рассчитываются из **фактического** бюджета. В `run_start` записываются `budget_tenths` и `budget_source`; в `run_end` — подтверждённый расход, неизвестный резерв, остаток и состояние OUT.

## Проверка решений и нерешаемости

- Математика: точные дроби, линейные ограничения, ограниченный перебор и проверка единственности искомого значения.
- Поиск и данные: типизированный `record_plan`, SQL и операции над базой знаний; фильтры, группировки, joins, UTC-время и сохранение равноприоритетных записей. Идентификаторы остаются строками. Явно запрошенное поле не подменяется количеством его значений.
- Код: отдельная копия, компиляция, публичные unittest, поддержанные явные контракты и дополнительные проверки. Граничные входы включают большие и отрицательные целые. Это не доказательство прохождения всех скрытых тестов.
- Пропуск: при подтверждённом конфликте, недостатке необходимых данных либо отсутствии проверенного ответа в пределах ресурсов. Ошибка собственного плана не считается доказательством невозможности всей задачи. За пропуск нерешаемой задачи баллы не начисляются.

Linux worker использует seccomp и, при Landlock ABI ≥3, ограничение файлового доступа staging-каталогом и stdlib. Сеть и создание процессов внутри worker запрещены. Без подходящего Landlock остаётся строгий режим без файлового ввода-вывода; такие coding-задачи могут остаться нерешёнными.

## Проверки перед сдачей

```sh
docker build --target bench -t ping-floyd:bench .
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  --entrypoint python ping-floyd:bench \
  -m unittest discover -s bench -t /app -p '*checks.py' -q

python3 -m bench.submission_smoke /tmp/pf-submission-check --image ping-floyd:contest
```

Проверки не требуют настоящего API-ключа. Они покрывают разные BUDGET, нулевой бюджет, приоритет окружения над CLI, конкурентные резервы, оба способа запуска контейнера, OUT, сохранность входов и защиту coding-worker. Скрипт smoke использует только стандартную библиотеку Python на хосте. Каталог результатов должен быть новым.

GitHub Actions настроен на сборку и эти проверки на Linux amd64 без секретов модели. Локально проверен Linux arm64. Успешная сборка amd64 сама по себе не подтверждает выполнение worker: эмуляция amd64 на Mac не поддерживает используемый seccomp. Фактический статус CI и измерения фиксируются в [отчёте подготовки к сдаче](docs/submission-20261113.md).

Сдаётся один образ `contest`. Ограничения: репозиторий без `.git` <100 МБ, образ <4 ГБ по `docker images`, сборка ≤1000 секунд, запуск ≤1 часа, не более 4 CPU, 16 ГБ RAM и пяти сессий. Исторический замер сборки без кеша установочных слоёв — 159,28 с при уже скачанном базовом образе; скорость сети жюри этим не гарантируется. Размер последних проверенных образов — около 1,39 ГБ.

## Результаты и воспроизводимость

Последнее парное сравнение на 32 английских задачах с 25% нерешаемых: **65/70 против 64/70**, расход **8317,2 против 8627,6** при бюджете 10 000 на вариант. Это небольшой авторский эксперимент, не статистическая гарантия выигрыша. Ошибки и ложные ответы на нерешаемые задачи сохраняются.

Генераторы находятся в `bench/`. Агенту монтируется только каталог задач; эталоны и скрытые тесты используются отдельно после прогона. `bench.independent_coding` дополнительно проверяет coding обычным unittest в отдельных контейнерах, независимо от worker харнесса.

Организаторский `tools/collect_harness_report.py` сохранён без изменений для возможной регистрации в agent-registry-mcp. Он собирает маркеры окружения и родительские процессы с хешем отчёта; в решении задач и конкурсном образе не используется. OpenJiuwen работает непосредственно, без имитации регистрационных маркеров.
