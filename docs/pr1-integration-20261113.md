## Что взято и исправлено

Оба файла `tests/test_review_*.py` перенесены **побайтно**: все 19 тестов автора, без изменения условий, исключения неудобных случаев и `expectedFailure`. Они включены в отдельный обязательный шаг GitHub Actions и только в стадию `bench`. В конкурсный образ тесты и fixtures не попадают. [Происхождение и команда запуска](../reviews/2026-11-12/README.md).

На базе эти тесты дали **17/19**. Оставались два случая:

- **R01, граница быстрого решателя.** `solve_fast` выбрасывал обычный ValueError при неизвестном соответствии полей. В полном workflow исключение уже перехватывалось и включался LLM, поэтому это не новый выигрыш полного workflow. Теперь сам интерфейс возвращает `None` для неподдержанной операции, пробует нормализованную формулировку и позволяет передать задачу модели. Доказанная неоднозначность `NoUniqueAnswer` и некорректные входы `InvalidInput` сохраняют отдельные исходы.
- **R11, последовательные вызовы.** Контракт со счётчиком уровня модуля и последовательными вызовами всё ещё ложно признавался противоречивым. Определение возможного состояния теперь учитывает время жизни данных и последовательные изменения, независимо от имени функции. Явно чистая/не хранящая состояние функция по-прежнему обязана давать одинаковый результат для одинаковых аргументов. Невозможность двух разных точных типов одного результата проверяется и для stateful-контракта.

Добавлены четыре собственные защитные проверки: сохранение типизированных отказов, разные формулировки состояния и имена функций, противоречие для чистой функции, несовместимые типы результата. Один старый собственный тест согласован с новым интерфейсом: для неопределённой задачи допустим `None` или доказанная неоднозначность, но **никакой ответ не допускается**. Раньше этот тест разрешал исключение «unsupported field mapping». Исходные тесты PR не менялись.

Это изменения границ доказательства и обработки неподдержанных операций, а не ответы по именам/ID задач. Распознавание формулировок состояния остаётся ограниченной эвристикой; оно не является полным семантическим анализом английского условия. Дополнительные проверки не гарантируют прохождения всех скрытых coding-тестов.

Старые сетевые/сборочные логи PR остаются историческими свидетельствами в PR, а не выдаются за текущие измерения.
