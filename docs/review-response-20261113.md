| Замечание | Изменение и границы |
|---|---|
| R01 — имя поля принимается за отсутствие данных | Неподдержанное соответствие полей в строгом `kb_lookup` возвращает ошибку плана, позволяя LLM исследовать другие поля. Конфликт известных значений по-прежнему означает неоднозначность. Проверены `Birth year` вместо `Born` и полный workflow. |
| R02 — average проходит публичный тест, нарушая пустой вход | Детерминированный ремонт отказывается от неподдержанного явного контракта пустого входа. Изначально зелёный неизменённый код теперь требует исполнимых дополнительных проверок из условия, а не только текста «review». Это снижает риск, но не доказывает выполнение произвольного контракта. |
| R03 — запрещены собственные файлы и stdlib | При доступном Landlock ABI ≥3 чтение/запись ограничены staging-каталогом, чтение stdlib разрешено; seccomp продолжает запрещать сеть и запуск процессов. Проверены `tomllib`, чтение/создание файла, отказ при выходе через symlink, записи вне staging и открытии сокета. После запуска проверяются хеши Python-файлов. На старом ядре без Landlock ABI ≥3 сохраняется строгий режим без файлового ввода-вывода. |
| R04 — любой 429 навсегда отключает прокси | При допустимом `Retry-After` — ограниченное ожидание и повторы в пределах deadline. Отказ без этого признака остаётся консервативным. Неизвестный расход сохраняется в резерве. Это поддержка семантики HTTP, а не утверждение о наблюдённом поведении NeuralDeep. |
| R05 — усечённый ответ теряется | `finish_reason=length` получает ограниченный повтор с большим выходным лимитом. Первый оплаченный ответ учитывается. Максимум три попытки, общий и задачный бюджеты сохраняются. |
| R06 — дата вместо года | Запрошенный год проецируется из корректной даты, проверены быстрый путь и поддержка доказательств. |
| R07 — факт из прозы не принимается | Поддержано ограниченное извлечение утвердительного факта рождения с привязкой к сущности вопроса. Это не универсальная проверка произвольной прозы. |
| R08 — допустимо только имя integer_inverse | Принимается также точный конечный перебор с указанными в вопросе границами и чётностью. Положительный тест выполняет настоящий workflow. Соответствие произвольных английских операций ограничениям всё ещё не доказано полностью. |
| R09 — цепочка длиннее исходного контекста | Подтверждённый результат lookup расширяет доступные сущности и файлы; произвольное новое имя без связи не разрешается. Проверен переход через три Mentor-связи. |
| R10 — необъяснимый total_tokens | Несогласованное usage не признаётся точным расходом: сохраняется резерв. Проверены reasoning внутри и отдельно от completion. |
| R11 — runtime-файл и состояние | Явно создаваемые вызывающим кодом файлы не объявляются отсутствующими исходными данными. Для явно stateful-контрактов отключено доказательство противоречия по повторным вызовам и неподходящие универсальные проверки. |
| R12 — нерелевантный пропуск блокирует ответ | Для конечных чисел `0 × неизвестное` не мешает сумме; ненулевой множитель сохраняет неопределённость. Кратчайший известный прямой путь не блокируется заведомо более длинной веткой с отсутствующей вершиной. |

Изменены две прежние регрессии, закреплявшие неверную семантику R01: отсутствие точного имени поля теперь означает неподдержанный план, а не доказанную невозможность. Проверки реальных конфликтов, защиты файлов и бюджетных ограничений сохранены.

## Восстановление задач и coding

При бюджете от 25 000 и остатке не менее половины после первого прохода автоматически включается ограниченный второй проход reasoning-моделью по задачам с `no_progress`, `step_limit` или `repair_limit`. Он расходует не более `--retry-share` (по умолчанию 10%) исходного бюджета. Пропуски с доказанной неоднозначностью в эту очередь не входят. `--no-auto-retry` отключает автоматический проход; `--retry-model` задаёт явную модель. При бюджете 5 000 автоматического второго прохода нет.

Проверки универсальных свойств строятся только из поддержанных явных условий, через разрешённое AST-подмножество. Среди проб есть отрицательные числа и числа за пределами точности float. Результаты не извлекаются из эталонов. Дополнительные проверки LLM тоже могут быть неверными: это проверяемая гипотеза модели, а не независимый oracle. После исправления кода скрытые тесты остаются необходимы.

Добавлен `bench.independent_coding`: обычный `unittest` в отдельном контейнере на каждую задачу, без импорта нашего worker/генератора контрактов. В контейнер попадают только одна задача и её скрытые тесты; сеть отключена. На предыдущем контрольном прогоне v2 он независимо подтвердил **13/19** правильных coding-решений. На свежем наборе все **19/19** эталонных реализаций прошли до запуска агента.

## Ограничения допуска и измерений

Проверено Linux arm64. Сборка amd64 отдельно не равна успешному запуску amd64: эмуляция на этом Mac не поддерживает используемое seccomp-ограничение. Защита ради зелёного теста не отключалась. На финальном стенде потребуются доступная архитектура и совместимое ядро; без Landlock ABI ≥3 файловые coding-задачи могут оставаться нерешёнными.

Холодная сборка зависит от сети. Повторная сборка amd64 без кеша установочных слоёв заняла **159,28 с**; базовый образ уже присутствовал локально. Это не гарантия укладывания в 1000 секунд у жюри. Неочевидные форматы: OUT — TSV, поскольку точная грамматика общего файла организаторами не описана; answer.txt находится рядом с task.json.

`collect_harness_report.py` изучен: он собирает `JIUWENSWARM_*`, цепочку родительских процессов и SHA-256 отчёта для agent-registry-mcp. Это не решатель и не способ уменьшения расхода. Он сохранён без изменений в `tools/` как необязательная регистрационная утилита. В рабочий образ не включён и при решении задач не запускается. Искусственные переменные или процессы для имитации чужого harness не создавались.

Первичные источники: [Landlock](https://docs.kernel.org/userspace-api/landlock.html), [HTTP 429 / Retry-After](https://www.rfc-editor.org/rfc/rfc6585#section-4). Архитектура отделения плана от точного исполнения родственна [PAL](https://proceedings.mlr.press/v202/gao23f.html); это известный исследовательский подход, а не заявка на новую научную теорию.
