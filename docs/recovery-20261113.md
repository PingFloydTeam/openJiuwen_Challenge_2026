# Ограниченное продолжение: поиск и время выполнения

Бейзлайн — опубликованный commit `1fd43f6964143f308aa3da2d5512ff4ae21c82af`. В этой итерации не менялись зависимости, модели, общий бюджет, число шагов или лимит исправлений кода.

Исправлены четыре общие причины потерь:

1. Полный `record_plan` с соединениями и проверкой единственности теперь допускается для переходов между структурированными файлами. Раньше эвристика требовала именно `linked_fact`, предназначенный для индексированных документов. Чтение одного фрагмента по-прежнему не подтверждает единственность.
2. Вложенное `j/field` принимается как `/j/field`, если буквального ключа `j/field` нет. Буквальные ключи, включая неизвестное значение, имеют приоритет. Тип вложенного числового поля сохраняется: ревизия `10` не сравнивается с `2` как строка. Для `records` поддержана эквивалентная форма `filter`; конфликт с `filters` отклоняется.
3. Явный запрос «return the unique badge» требует значения поля badge. Результат `count_distinct(badge)` больше не может завершить такую задачу. Это ограниченная грамматика явного запроса поля, а не полное понимание произвольного текста.
4. Установленный openJiuwen по умолчанию ограничивал **весь workflow 60 секундами**. Вызов SDK теперь получает `min(180, остаток общего времени)`. Ограничения API-запросов, токенов, шагов и внешний deadline сохранены; бесконечного ожидания нет.

## Проверка и эксперимент

**116 уникальных регрессионных тестов прошли за 27,609 с** в Linux arm64 с read-only rootfs, seccomp/Landlock, cap-drop ALL и no-new-privileges. Новые проверки включают конфликтующие ties, буквальный ключ со слешем, сохранение числового типа, отказ принять количество вместо значения и передачу deadline в SDK. Исходные проверки защиты файлов и бюджета сохранены.

Кандидат зафиксирован до генерации контрольных входов. `bench.recovery_suite` создаёт 32 английские задачи: по 8 каждого типа, в каждой группе 6 решаемых и 2 нерешаемые. Итого **25% нерешаемых**. Все семейства исходного генератора представлены; это новые экземпляры знакомых семейств, не независимый внешний тест. Seed — `2026111302`. Все шесть coding-эталонов заранее прошли независимый unittest.

Обе версии получают одинаковые задачи, `qwen3.8-27b-noreason`, одну сессию, **10 000 выходных эквивалентов и 600 секунд**. Суммарный предел живого эксперимента — **20 000** эквивалентов с учётом консервативных резервов. При этом бюджете автоматического второго прохода нет. Агент видит только задачи без expected; oracle и скрытые тесты монтируются отдельно при проверке.

Расход кандидата ниже на **3,6%**, но его время выше: задержки сервиса не контролируются этим экспериментом. Пиковая память кандидата — 231567360 байт; образ — **1,39 GB** по `docker images`.

Математика и анализ данных — 6/6 у обеих версий. Поиск — 4/6 → 5/6: исправлен ответ количеством вместо значения. Coding — 5/6 у обеих версий, подтверждено независимым judge; одна задача перешла из пропуска в неверный ответ и по-прежнему не принесла баллов. Один пропуск в поиске и один ложный ответ на нерешаемую задачу анализа данных сохраняются. Таким образом, прирост небольшой и не означает устранения всех слабостей.

Официальные примеры финальной версии: **8/8, 20/20, 0 токенов**. Снимок OUT совпадает с ответами, входные task.json и публичные тесты не изменены, расход в траекториях сходится с итоговым счётчиком.

Артефакты: `benchmarks/recovery-20261113/`. В них сохранены входы, хеши исходников, траектории, оценки, usage и результаты независимого coding-judge. API-ключи не сохраняются. При недостаточной определённости плана ошибки всё ещё возможны: в частности, эта итерация не добавляет полноценную проверку валют и единиц измерения.

## Лимиты и воспроизведение

Финальный runtime не получает новых зависимостей или весов. Docker по-прежнему ограничен 4 CPU, 16 GB RAM, 512 процессами и tmpfs 2 GB. Проверена сборка amd64, но нативное выполнение coding-worker на amd64 остаётся непроверенным; известное ограничение seccomp в эмуляции Mac не обходится.

```sh
docker build --target contest -t ping-floyd:contest .
docker build --target bench -t ping-floyd:bench .
python3 -m bench.recovery_suite /tmp/pf-recovery --seed 2026111302
python3 -m bench.validation /tmp/pf-recovery /tmp/pf-recovery-run \
  --image ping-floyd:contest --bench-image ping-floyd:bench \
  --live --budget 10000 --seconds 600
python3 -m bench.independent_coding /tmp/pf-recovery-run/suite --image ping-floyd:bench
```

Для точного парного воспроизведения бейзлайн собирается из commit `1fd43f6`; его нельзя заменять текущей версией. Результаты этого небольшого эксперимента не заменяют проверку на финальном наборе жюри и не дают статистической гарантии выигрыша.
